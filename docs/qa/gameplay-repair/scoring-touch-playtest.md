## Method and boundaries

Use the installed tested Debug build on the dedicated iPhone SE. Preserve its pre-test save and profile before any persistence case; never touch the user's large-phone save. Use the QA menu only to arrange starting state. Activate owned Buffs, select exact hand cards, place digits, change Bookmark order, End Turn, Keep Filling and Cash Out through the native player controls. UI reads and touches use CUA. Capture the preview, final ledger and visible wallet/score; inspect saved JSON only as corroboration, never as a substitute for player input.

The seven scoring fixtures start with zero banked/queued score and conserve cards. Their loader deliberately disables saving, so they cannot establish restart persistence. A separate normal persisted run, after backup, must establish queued state, UUID/order, ledger and exactly-once banking across restart. QA Force Boss changes the selected modifier but does not turn an ordinary puzzle into a mandatory boss encounter; the fractional test below proves arithmetic only. Mandatory encounter coverage belongs to the flow/catalogue testers.

Expected numbers below are calculated from the printed rules and fixed Latin board, not queried from scoring helpers. The board solution is `((row × 3 + floor(row / 3) + column) mod 9) + 1` with zero-based row/column. R1C5 and R2C2 are both five. Fixture preparation is not an effect activation.
