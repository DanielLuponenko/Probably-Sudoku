# Enlarged-display, lifetime and edge-case audit

Started 19 September 2026. This audit extends the previous graphics pass; that pass is not evidence that enlargement or memory stress was already covered.

## Required evidence

- Core briefing, puzzle, results, Shop, completion, and decision panels remain usable at reduced logical viewport sizes and enlarged text, including intermediate reflow points and AX5.
- Important copy actually enlarges; a layout that merely keeps fixed small fonts is not a successful larger-text check.
- Board/hand/selection, scoring, inventory and saved state remain unchanged by layout changes or inspection. Required actions and dismissals stay reachable.
- Real simulator accessibility settings are exercised independently. Display Zoom, Dynamic Type and accessibility magnification are distinguished.
- Repeated model/view/renderer/scene creation and teardown release owners and snapshots. Short-lived animation retention is distinguished from permanent leaks and bounded framework caches.
- Actual app-process memory is measured at comparable settled points through repeated navigation; leak scans supplement weak-reference tests rather than replace them.
- Confirmed fixes receive regression tests and independent native rechecks. Player data and isolated simulator settings are preserved.

## Environment and limitations

The isolated iPhone 17 Pro and SE simulators run iOS 26.3. Their Settings expose accessibility text enlargement but the tested iPhone simulator does not expose the physical phone's Display Zoom setting. Hosted tests therefore use explicitly identified logical viewports; those captures are not described as native Display Zoom screenshots. Apple's [display/text settings guide](https://support.apple.com/en-ca/guide/iphone/iphd6804774e/ios) and [UIScreen bounds documentation](https://developer.apple.com/documentation/uikit/uiscreen/bounds) describe the relevant distinction between display settings and dimensions measured in points.

Physical iPhones were discovered but have not been modified or used. No whole-system profiling is performed. Runtime graphs concern only isolated test app processes and are saved without allocation content descriptions.

## Memory ownership findings and regression evidence

- **Confirmed bounded retention, not a permanent leak:** number-return, line-clear and effect-receipt cleanup Tasks captured the entire `GameModel` for 0.85, 1.1 and 3 seconds respectively after its Book was abandoned. Before the fix, three focused tests failed all **18 immediate weak-reference assertions** across repeated real gameplay actions. The model remained reachable through a pending timer; this was not an unreachable allocation cycle. Evidence: `/tmp/nc-enlarged-memory-red3.log`.
- The three cleanup closures now capture the model weakly. Their original durations and current-event checks remain intact. A separate live-owner regression verifies that presentation still expires and that the encoded Game remains unchanged.
- The focused green gate passed **9 tests, zero failures, in 9.916 seconds**: immediate model release, normal presentation expiry, four real puzzle/Metal host cycles alternating completion and cancellation, four nested paper-host removals, three real stand teardown cycles, twenty released return snapshots, six prepared-game retirements, and a timed boss owner. Evidence: `/tmp/nc-enlarged-memory-green1.log`; tests are in `AppTests/MemoryLifecycleTests.swift` and `AppTests/MemoryHostLifecycleTests.swift`.
- **Fixture correction:** the first stand test created SceneKit views that never entered a window, then expected normal UIKit removal behavior. Its retained scene/view observations did not prove a production leak. The corrected test mounts and removes a real window-hosted stand, including a pending frame callback; all three cycles release the coordinator, scene, view and callback owner without a production SceneKit change. The clock fixture was also corrected from an intentionally frozen render-only model to a nonpersisting resumed model.
- `ContentView` now drops its retired model after successful abandonment or completed-Book closure, instead of keeping one previous Game while the menu is open. Source review confirms that failed deletion retains the owner, completion identity is copied before release, and existing identity/token guards reject old callbacks. The return transition retains its captured pixels independently.
- These checks establish owner release in the tested paths, not a claim that all process memory returns to launch size. The page renderer has fixed mesh/uniform resources and releases its current texture on cancellation. Stand caches belong to the coordinator; the title cache already keeps only the identity and current benefit images. Shared UIKit/Metal/SceneKit residency is assessed separately through the native process measurements below.

The independent reviewer also performed 30 same-process native navigation cycles (120 actions). App-only scans found zero leaks at the baseline, after 15 cycles and after 30 cycles. The allocated heap grew only 8 KB between the latter two settled samples, while physical footprint changed from 129.9 to 130.9 MB. The full sampling method, build identity and limits are in [memory measurements](memory-measurements.md).
